# سير عمل التطوير والوكلاء

## التسلسل الإلزامي لكل مهمة
1. **Inspect**: افحص الملفات الحالية والعقود والاختبارات والحالة في Git. لا تفترض أن الملف مفقود قبل البحث.
2. **Plan**: حدد النطاق والملفات المتأثرة والاختبارات والمخاطر.
3. **Implement**: أصغر تغيير متكامل، مع إعادة استخدام الخدمات والمكونات الموجودة.
4. **Verify**: شغّل الفحوص الملائمة فعليًا، ولا تكتفِ بقراءة الكود.
5. **Review**: راجع diff، الأسرار، الصلاحيات، العزل، التبعيات، والتوافق.
6. **Report**: اذكر الملفات التي تغيرت، الأوامر ونتائجها، وما بقي، وأي اختبار لم يُشغّل.

## قواعد الوكلاء
- الوكيل الباحث يجمع الأدلة وروابط الملفات دون تعديل.
- المخطط يحدد حدود المجال والعقود والاعتماديات قبل التنفيذ.
- المنفذ يعمل ضمن نطاق ملفات معلن، ولا ينشئ Runtime أو Router أو Auth أو Database بديلًا.
- المراجع يراجع diff والاختبارات والأمان باستقلال عن المنفذ.
- لا يعمل وكيلان على الملف نفسه بالتوازي.
- لا تُدمج تغييرات الوكلاء تلقائيًا؛ يلزم دمج واضح ومراجعة واختبارات.

## حدود التنفيذ
- لا تعديل على قاعدة إنتاج أو migrations إنتاجية دون خطة ترحيل ونسخة احتياطية وموافقة صريحة.
- لا قراءة أو طباعة أسرار البيئة؛ افحص وجود المتغيرات فقط، ولا تدرج قيمها في السجلات.
- لا إرسال رسائل حقيقية للعملاء ولا تحصيل أموال ولا احتساب عمولات نهائية في وضع الاختبار.
- أي تكامل خارجي يبدأ بـmock أو sandbox، ثم اختبار قبول محدود.
- عند فشل اختبار، لا تخفِه ولا تتجاوزه لإنتاج نتيجة خضراء شكلية.

## صيغة التقرير النهائي
- الحالة: PASS / FAIL / BLOCKED لكل بوابة.
- الملفات المتغيرة.
- الفحوص التي شُغلت حرفيًا والنتائج.
- المخاطر المتبقية.
- الخطوة التالية الواحدة.

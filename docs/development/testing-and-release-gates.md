# بوابات الاختبار والإطلاق

## Gate 0 — مراجعة التغيير
- diff مفهوم ومحدود.
- لا أسرار أو ملفات بيئة أو بيانات شخصية.
- لا تعارضات ولا تغييرات غير مقصودة.
- تحديث الوثائق عند تغير العقد أو السلوك.

## Gate 1 — جودة المصدر
- تثبيت dependencies وفق lockfile.
- lint.
- typecheck.
- unit tests.
- اختبار migrations على قاعدة فارغة/مؤقتة.
- فحص التبعيات والثغرات والأسرار.

## Gate 2 — المجال وقاعدة البيانات
- اختبارات انتقالات حالة أمر العمل والحجز.
- قيود المبالغ والضريبة والخصم.
- موافقة العميل قبل الأعمال الإضافية وفق السياسة.
- منع التكرار باستخدام قيود قاعدة البيانات وidempotency.
- اختبارات RLS بمستأجرين وأدوار متعددة.
- اختبارات الملفات والتقارير الخاصة.

## Gate 3 — التكامل
- API contract tests.
- اختبارات المصادقة وانتهاء الجلسة وتغيير الدور.
- اختبارات رفع/تنزيل المستندات.
- محاكاة فشل الشبكة وإعادة الطلب.
- استيراد ملفات تشخيص معروفة وصيغ غير صالحة.

## Gate 4 — قبول الواجهة
- RTL والعربية على شاشة iPhone صغيرة وشاشة سطح مكتب.
- رحلة كاملة: استقبال ← تشخيص ← تقدير ← موافقة ← تنفيذ ← جودة ← فاتورة/تحصيل ← تسليم.
- رحلة العميل لعرض الموافقة والمستندات المنشورة.
- لا يُختبر إلا ببيانات تجريبية غير حساسة.

## Gate 5 — ما قبل الإنتاج
- build إنتاج ناجح.
- ترحيل قاعدة البيانات في بيئة staging أولًا.
- فحص متغيرات البيئة دون إظهار قيم الأسرار.
- smoke tests للمصادقة وAPI وقاعدة البيانات والتخزين.
- مراجعة النسخ الاحتياطي وخطة rollback.
- الموافقة على الإصدار وتوثيق commit وإصدار migration.

## شروط الإيقاف
- أي فشل في عزل الورش أو المصادقة أو صلاحيات المال/الموافقة.
- migration مدمرة أو غير قابلة للرجوع دون خطة.
- فشل build أو اختبار مطلوب.
- وجود سر أو بيانات عميل في المستودع.
- فحص لم يُشغّل يُسجل BLOCKED، وليس PASS.

## بعد النشر
- smoke test ببيانات اختبار.
- مراقبة الأخطاء والوقت والاستجابة.
- تأكيد مسار rollback قبل إدخال بيانات حقيقية.

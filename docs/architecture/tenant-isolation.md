# عزل بيانات الورش (Tenant Isolation)

## قاعدة غير قابلة للتفاوض
كل سجل خاص بورشة يجب أن يكون مرتبطًا بمستأجر واضح، وكل قراءة أو كتابة تتحقق من عضوية المستخدم وصلاحيته وملكية المورد على الخادم وقاعدة البيانات. إخفاء عناصر الواجهة وحده ليس عزلًا.

## متطلبات المخطط
- جدول `workshops` يمثل المستأجر.
- بيانات الموظفين مرتبطة بـ`workshop_id` وعضوية نشطة ودور.
- الجداول التشغيلية تحمل `workshop_id` مباشرة عندما يكون ذلك مناسبًا، مع مفاتيح خارجية مركبة أو قيود تضمن أن العلاقات التابعة تنتمي إلى الورشة نفسها.
- لا يقبل الخادم `workshop_id` المرسل من متصفح غير موثوق كمرجع للصلاحية.
- المستخدم ذو عضوية في عدة ورش يحتاج اختيار سياق صريحًا وتحققًا خادميًا من العضوية في كل طلب.
- حساب مالك المنصة منفصل عن أدوار الورشة، ولا يمنحه الدور العام تلقائيًا حق تصفح بيانات العملاء.

## متطلبات قاعدة البيانات
- تفعيل RLS على كل جدول يحتوي بيانات مستأجر أو مرجعًا إليها.
- سياسات SELECT/INSERT/UPDATE/DELETE منفصلة ومحددة، مع `USING` و`WITH CHECK` حيث يلزم.
- أي RPC بصلاحيات مرتفعة يجب أن يتحقق داخليًا من الهوية والدور والورشة، ويستخدم `search_path` آمنًا ويمنع التنفيذ العام غير المقصود.
- لا يُستخدم service-role key إلا على الخادم وفي عمليات ضيقة محددة؛ لا يصل إلى العميل أو تطبيق الجوال.
- لا يكفي وجود عمود `workshop_id` دون سياسات RLS واختبارات سلبية.

## الملفات والتخزين
- كل ملف خاص مرتبط بورشة وبالمورد المالك.
- التخزين private افتراضيًا؛ الوصول عبر جلسة وصلاحية أو رابط مؤقت محدود.
- يجب التحقق من أن سجل الملف والعميل والسيارة وأمر العمل تتبع الورشة نفسها قبل الإصدار أو التنزيل.
- التحقق من نوع الملف وحجمه واسم آمن، ومنع كشف مسارات داخلية.

## الاختبارات الإلزامية
1. موظف الورشة A لا يقرأ ولا يعدّل بيانات الورشة B بتغيير ID في URL أو body.
2. لا يمكن ربط سيارة من الورشة B بعميل أو أمر عمل من الورشة A.
3. العميل يرى ملفه وسياراته وأوامره وموافقاته ومستنداته المنشورة فقط.
4. الفني لا ينفذ إدارة مستخدمين أو إجراءات مالية غير مخولة.
5. مستخدم غير مصادق لا يصل إلى API خاص أو ملفات خاصة.
6. محاولات التلاعب بالـRPC وStorage لا تتجاوز RLS.
7. اختبارات التكرار تمنع إنشاء أمر عمل أو تحصيل أو عمولة مرتين.
8. تُشغّل الاختبارات على قاعدة اختبار بمستأجرين على الأقل قبل كل إطلاق.

## بوابة الإصدار
لا يُقبل أي إصدار قبل نجاح اختبارات العزل الإيجابية والسلبية على قاعدة بيانات فعلية للاختبار، مع حفظ النتائج كأثر CI. لا يُجرّب اختبار الأمان على بيانات إنتاج حقيقية.
